# Сравнение Git и SVN

## 1. Почему в Git ветвление «дешёвое», а в SVN — «дорогое»?

В Git ветка — это просто указатель на коммит (файл размером ~41 байт в .git/refs/heads/). Создание ветки мгновенно, переключение — тоже. Git хранит историю как граф коммитов, и все ветки живут в одном репозитории, не копируя файлы.

В SVN ветка — это физическая копия директории внутри репозитория. Хоть SVN и использует hardlinks для экономии места, всё равно при создании ветки он проходит по всем файлам и копирует структуру. Переключение между ветками медленное, а merge — ручной и часто с потерями.

## 2. Можно ли в SVN сделать коммит без интернета? Почему?

Нет. SVN — централизованная система контроля версий. Вся история и все файлы хранятся только на центральном сервере. Локально у разработчика есть только рабочая копия, но коммит обязательно отправляется на сервер. Без сети коммит невозможен.

В Git коммит делается локально (в свой полный репозиторий), а связь с сервером нужна только для push/pull. Поэтому в самолёте или при плохом Wi-Fi Git продолжает работать в полную силу.

## 3. В каких сценариях SVN до сих пор может быть предпочтительнее Git?

- Legacy-проекты в госсекторе, банках и крупных корпорациях, где SVN уже настроен, а миграция на Git стоит дорого.
- Жёсткий контроль доступа к отдельным папкам — в SVN права настраиваются по путям, в Git это сложнее.
- Очень большие бинарные файлы (CAD, дизайн, медиа) — SVN умеет блокировать файл (svn lock), чтобы его не редактировали одновременно.
- Простые проекты с линейной историей, где не нужны ветки и распределённая работа.
- Полный контроль над всей историей — в SVN легко посмотреть, кто что менял в любой момент.
